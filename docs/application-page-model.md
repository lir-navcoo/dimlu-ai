# 应用与页面模型

## 核心概念

- **应用**是可独立保存、配置和运行的低代码交付单元。它有稳定的 `id`、`title`、`entryPageId`，并集中管理页面和组件、动作、计算及数据传输依赖。
- **页面**是应用内可独立设计和访问的界面。页面拥有自己的组件树、状态、表单、数据源、代码样式及进入动作；页面通过应用内路由切换，不是一个独立应用。
- **自定义方法**属于应用逻辑，不属于单个页面的组件树。页面控件事件通过动作调用应用方法；页面特有行为仍可留在页面生命周期和事件动作中。
- 工作台的「页面逻辑」和组件设置的「事件」页签都能打开「应用自定义方法」弹窗编写可复用 JS。新方法在保存时创建，删除已有方法需要确认。页面进入动作在「页面逻辑」配置，页面状态、表单模型和数据源集中在「数据」面板。
- 编辑器中的页面管理、应用设置是开发工具路由，不是最终用户访问的应用页面。

## 当前实现

应用与页面定义保存在 `ApplicationSchema`：应用目录可创建并切换多个本地应用，每个目录条目有独立项目存储键，导入 JSON 替换 Schema `id` 时目录键仍稳定。应用内包含多个页面。首次升级会把旧 `dimlu.workbench.project.v1` 复制到新应用存储并保留旧键；单应用旧记录如果损坏，会继续进入受保护恢复流程，不会被空白项目覆盖。编辑器分别使用 `/editor/apps`、`/editor/application`、`/editor/pages` 与 `/editor/page/:pageId` 管理应用目录、应用配置、页面清单和页面搭建。

应用设置当前允许修改应用名称、应用 ID 和入口页面。修改应用 ID 会验证字符规则与目录唯一性，迁移目录索引和项目存储键，保留旧键作为本地备份。页面清单负责新增、复制、排序、分组、设入口及删除页面。入口页是应用启动时的默认页面，不限制其他页面被单独路由访问。

应用设置中的“自定义方法”允许创建应用级 JavaScript 方法。方法定义包含稳定 ID、显示名称、`payload` 输入类型、返回值类型和函数体；函数体通过 `input.payload` 读取参数，通过 `context` 使用当前页面的 `getState`/`setState`、表单操作、数据源执行和 UI effect。页面事件与 `onEnter` 动作列表中以 `app.method.<methodId>` 选择调用，结果可绑定到页面状态。方法代码仅在调用时执行，保存阶段只做语法构造检查；代码与页面代码一样在当前窗口运行，不是安全沙箱，只应运行可信作者提供的代码。

这些路径是**编辑器路由**。运行时路由使用 `/apps/:appId` 与 `/apps/:appId/pages/:pageId`：应用级路径解析到 `entryPageId`，显式页面路径解析到对应页面，未知应用/页面与格式错误路径均保留为显式错误。搭建工作台的“运行应用”会进入该运行时页面宿主，支持页面选择、`app.navigate` 页面事件动作、浏览器前进/后退、运行时组件渲染和重新加载后由本地项目恢复定义。事件面板为 `app.navigate` 提供本应用页面选择器，静态目标在保存时校验；运行时仍再次校验目标，调用可选 `replace` 控制是否替换当前历史项。应用目录可保存多个应用，运行 URL 可直接解析目录中的非活动应用；发布端和跨设备应用部署尚未实现。

## 后续建设边界

1. 应用目录当前提供本地创建/切换/复制/移除和 ID 重命名；删除仅从目录移除并保留存储字节，后续补充可审计的物理清理、导入冲突交互及目录损坏恢复入口。
2. 运行时路由当前绑定本机活动应用；部署态的多应用寻址以及应用/页面故障后的完整恢复流程仍待建设。
3. 扩展自定义方法为多参数编辑、调试与诊断，并在需要隔离不可信作者代码的部署形态下设计真正的执行隔离；当前 MVP 使用单个类型化 `payload`，不可把页面整段 JSX 作为自定义方法的替代物。
4. 再建设发布、权限、后端数据服务等平台能力；当前阶段聚焦搭建层，不把它们伪装成已经具备的功能。
