# 基础组件第一阶段

本轮在 React 运行时基础上新增 19 项通用物料，物料面板从 12 项扩充到 31 项，另提供消息通知动作。组件实现、运行契约和编辑元数据分开维护，继续使用 Base UI、Tailwind CSS 与 Lucide。原有示例专用组件继续兼容，但不重新放回物料面板。

## 已实现范围

| 类别     | 新增物料或增强                   | 主要能力                                                                               |
| -------- | -------------------------------- | -------------------------------------------------------------------------------------- |
| 输入     | 单选组、多选组                   | 文本/数字实际值、禁用选项、横向/纵向、字段绑定、校验与重置                             |
| 时间     | 日期选择、时间选择               | 日期/年月/本地日期时间、时间、范围、内置清空、合法日期与起止顺序校验                   |
| 明细     | 通用动态明细                     | 独立使用或绑定表单数组、增删排序、稳定行身份、嵌套业务路径、逐字段校验、行数限制       |
| 布局     | 卡片、分隔线、标签页、标签页面板 | 内容与具名插槽、水平/垂直分隔、页签切换与内容保留                                      |
| 展示     | 图片、链接、描述列表             | 图片失败占位/预览、链接协议校验、详情多列布局                                          |
| 数据     | 数据表格、数据列表、分页器       | 稳定行 key、排序、分页、行选择、作用域插槽、加载/错误/空状态和重试事件                 |
| 反馈     | 对话框、抽屉、提醒、加载状态     | 焦点管理、Escape/遮罩关闭、异步确认、可关闭提醒、局部加载及交互阻止                    |
| 动作     | `ui.notify`                      | 信息/成功/警告/错误通知、超时、页面实例隔离及销毁保护                                  |

物料 ID 和参数以 `src/materials/` 中的契约为准，`src/editor/extended-catalog.ts` 提供默认值及属性设置器。所有默认片段均经过插入、编译和渲染验证。

## 体验示例

在文件菜单导入 `public/examples/components.json`，或在 Schema 调试区粘贴其内容并“校验并应用”。页面选择器中包含“表单组件”“数据展示”“布局容器”“交互反馈”。切换预览模式启用业务交互。

示例使用内存数据与通知动作，不向服务端保存数据。编辑内容保存在当前文档内，刷新前可导出 JSON。

## 字段值与 React 接口

单选组保留 `0` 与 `"0"` 的区别；多选组返回实际值数组。与现有选择器一样，配置了回调时使用 `value/onValueChange` 受控语义；未配置回调时保留本地交互状态。布尔控件继续使用 `checked/onCheckedChange`，输入框继续使用原生 React 输入事件。

日期、年月、时间与本地日期时间分别存储为 `YYYY-MM-DD`、`YYYY-MM`、`HH:mm[:ss]`、`YYYY-MM-DDTHH:mm[:ss]` 文本，不隐式转换时区。单值空值为 `""`，范围空值为 `[]`，范围有值时为两个字符串。中间输入可暂时不完整，但校验不通过时不能提交。范围允许同一天或同一时刻作为起止值。

范围字段示例：

```json
{
  "id": "period",
  "path": ["period"],
  "label": "生效范围",
  "type": "array",
  "itemType": "string",
  "uniqueItems": false,
  "format": "date",
  "range": true,
  "initial": []
}
```

字段的 `format/range` 必须与日期控件一致。通过组件入口新建字段时会建议匹配的模型。已绑定组件更改日期模式/范围前需先解除绑定，避免同时改变既有业务模型的类型。普通数组仍默认去重，只有显式 `uniqueItems:false` 才允许重复；旧多选字段保持原有语义。

## 通用动态明细

独立模式配置 `fields/value/minItems/maxItems/options`。表单内可在属性检查器的“明细模型绑定”选择已有数组，或编辑 JSON 模型定义并“保存并绑定明细”。模型保存、绑定和解除绑定都是原子命令，可撤销。

绑定模式以表单模型为唯一来源，与表单统一提交和重置；移动到所属表单外会被拦截。解除绑定会把模型默认字段、初始行和行数限制复制为独立配置，不复制预览中尚未保存的输入。

行内字段支持文本、数字、布尔、日期/时间，以及通过 `options` 提供的单选或多选。行 ID 只用于运行时身份，不进入提交数据；控件本地状态、值和错误在行排序时跟随稳定身份。受控父组件回传本次编辑值时保持当前行和焦点；外部替换整份明细数据会重新初始化本地明细。

当前不支持嵌套明细、异步字段校验或任意可视化行模板，复杂行内容仍可直接使用 `useFieldArray` 编写 TSX。

## 表格与插槽

数据是对象数组，`rowKey` 默认为 `id`，可使用 `record.id` 这样的嵌套路径，要求每行具有唯一的非空文本或有限数字标识。数字 key 和文本 key 分开。表格列配置包含 `key/title/width/sortable/align`。

`cell` 插槽提供 `row/column/value/index`，`actions` 提供 `row/index`，列表 `item` 提供 `item/index`。Schema 中使用普通表达式，如 `scope.row.name`；React 中直接调用 `slots.cell?.(params, stableKey)`。插槽实例的动作执行通道包含稳定 key，分别点击两行不会互相取消。自定义 React 列表/表格反复调用同一个插槽时，也应传入稳定 key。

空插槽保留默认单元格展示，避免刚拖入表格就看不到内容。编辑模式提供插槽落点，预览模式去除这些落点。表格分页与排序目前在客户端完成；外置分页器可通过 `onPageChange/onPageSizeChange` 对接后续查询逻辑。服务端查询、后端分页、远程排序、虚拟滚动、列固定/拖宽/编辑均未实现。

## 弹层与反馈

编辑模式中，对话框和抽屉展开为画布内的内容区，避免焦点锁定；预览模式启用 Base UI 的真实弹层。Portal 使用稳定容器，关闭和模式切换不重新挂载内容。实际弹层固定在视口，Escape 关闭后焦点返回触发按钮。

`onConfirm` 可直接返回 Promise。等待时禁用关闭和确认，失败保留弹层并展示错误，成功后关闭。Schema 确认动作也传递失败，保持相同语义。`footer` 插槽可替换底部操作。

消息通知通过 `ui.notify` 动作调用，不作为可拖入的常驻组件。宿主需渲染 `<MaterialEffects runtime={runtime} />`；工作台已接入，多个运行实例相互隔离，已销毁实例不能继续发出通知。图标操作的悬浮提示使用 Base UI Tooltip。

## 当前边界

- 日期和时间已升级为 Base UI Popover 承载的页面内日历/时间面板，保留 Base UI Input 与原字段格式；不使用浏览器原生选择弹层。操作说明见 [日期与时间](temporal-controls.md)。快捷范围、业务禁用日期和时区选择仍未提供。
- 表格列/数据、描述项及明细字段主要通过 JSON 设置器配置，还没有独立的可视化列设计器。
- 标签页面板应放入标签页容器；页面值为空时自动生成内部身份，需要受控切换时应填写唯一显式值。重复值会报告错误，尚未提供通用的父子组件白名单配置。
- 表单只读使用禁用 fieldset；错误汇总采集当前渲染的字段错误，并可定位和聚焦输入。它不替代 FormRuntime 的校验，也不自动生成业务提交服务。
- 布局滚动只作用于配置的内容区域，工作台外层继续保持全高不滚动。

## 验证

新增交互测试覆盖物料默认片段、类型化选项、时间格式与范围、明细行身份、绑定和撤销、表格选择/分页/排序/插槽作用域、弹层状态与异步错误、通知实例隔离。保留原有运行时、字段绑定、拖拽和编辑器回归测试。

基础组件阶段的浏览器验收包含日期范围与明细提交、表格行事件、对话框焦点恢复、抽屉定位、编辑与预览呈现及外层高度。日期时间的选择界面随后升级为页面内 Popover；直接输入继续兼容 input/change 并去重值回调，最新交互边界见 [日期与时间](temporal-controls.md)。
