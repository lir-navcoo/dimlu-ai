# 采购申请管理案例

新的默认案例使用单个业务页面：查询采购申请、服务端分页与排序、新建或编辑抽屉、基本信息和动态明细、金额派生、校验、提交并刷新列表。界面由通用物料与 Node.style 组合，不包含成员行、摘要、React 计数器或技术表单状态块。

## 使用

新浏览器环境首次进入使用该案例。已有合法 v1 本地项目始终优先恢复，存储键与版本不变，不会自动替换用户定义。要在已有项目之外查看，可下载 [采购管理 JSON](../public/examples/purchase-management.json)，通过文件菜单导入；导入会成为当前文档修改，可撤销。文件菜单也提供案例下载入口，下载本身不会改变当前项目。只有明确确认“重置项目”才会使用新默认案例重建文档和会话。

初始为编辑模式，不执行查询；切换预览后首次加载16条演示申请。搜索支持申请编号、申请名称、申请人和部门，点击查询才请求；切换页码、每页条数和表头排序由本地服务处理，表格不做第二次分页或排序。列表显示加载、空态、错误和重试入口。

“新建申请”先重置表单与已保存标记，再打开抽屉；“编辑”从对应记录精确回填基本字段与全部明细。新建、编辑以及重新打开不同申请不会混用旧的标量或明细行。抽屉由外部操作控制，通过通用 `showTrigger: false` 隐藏重复触发按钮；该可选属性默认 true，旧弹层行为不变。抽屉主体使用现有内容滚动布局，不改变工作台全高外壳。

## 字段、金额与提交

基本字段为申请名称、申请人、所属部门和采购日期；明细为物品名称、数量和预计单价。明细使用通用 `ui.fieldArray`，支持增加、删除与排序，运行时稳定行身份使输入、校验和焦点归属跟随记录。允许1–20行，数量为1–999的正整数；单价为非负金额，0有效，最多两位小数。基本信息必填，日期须为有效日期。

合计复用 `purchase.total` 与普通 TypeScript 金额函数，以整数分汇总逐行金额。超过10,000元显示并要求审批说明；整单不得超过50,000元。普通文字、标签、提醒和表单错误汇总呈现业务反馈。浏览器表单校验和本地服务均校验关键规则；服务从提交明细重算金额，不信任客户端回传的 amount。

提交通过表单统一通道执行一次 mutation。提交中禁用重复操作；成功后立即设置已保存标记并刷新列表，再通知并关闭抽屉。创建返回稳定的新ID；编辑未知ID拒绝。校验或保存失败保留输入。若保存已经完成而列表刷新失败，抽屉保留“申请已保存”提示与“仅重试刷新”按钮；该路径只执行 query，不能再次写入。新建和编辑新会话才重置已保存标记。

## 演示数据边界

`src/purchase-transports.ts` 是隔离工厂创建的本地 TypeScript 服务，支持查询取消，复用运行时 query latest-wins 和 mutation busy 保护。数据仅在当前模块实例内存中，刷新页面恢复初始记录；浏览器项目存储仍只保存应用定义与编辑位置，不保存业务记录、运行值、查询结果或未提交草稿。本例不请求真实业务服务，没有删除或审批流功能。

可在独立演示环境验证失败处理：查询“查询失败”触发查询错误；申请名称含“保存失败”触发保存拒绝；名称含“刷新失败”则保存成功后仅下一次列表查询失败。这些注入只用于本地测试，业务界面无需显示实现说明。

`public/examples/starter.json` 与 `purchase-management.json` 均由新业务案例导出。产品入口仅提供采购管理案例。旧三页技术案例不再生成或公开下载；其 `src/examples.ts` 定义仅供内部兼容回归使用，不影响已有项目恢复。独立动作、数据源、服务端列表和组件示例继续用于专项能力演示。HTTP、出码、完整插件、页面CRUD不属于本轮。
