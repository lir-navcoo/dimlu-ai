# 编辑器 v0.4：表单与字段绑定

本阶段把已有 FormDefinition 和字段适配器接入属性面板。应用 Schema、运行时、React 原生事件和 Hooks 契约保持不变，字段值仍只由 FormRuntime 持有，不镜像到页面 state。

## 使用流程

1. 添加并选中表单容器，点击“创建表单模型”。输入表单 ID 和首个字段的 ID、数据路径、名称、类型、默认值及校验，点击“创建并绑定表单”。模型至少有一个字段；创建模型和绑定容器是一次原子提交。
2. 在容器中加入文本输入或数字输入。选中输入组件后，在“绑定字段”中选择同类型的字段；仅提供最近表单容器模型的兼容字段。容器外不提供新绑定入口。下拉项显示模型 ID、字段名称及字段 ID。
3. 也可以展开“本页表单模型”，选择管理的模型，点击“新建字段”。选中字段组件时自动使用其适配类型，“创建并绑定字段”同时创建模型字段并绑定当前组件；其他组件下可以独立创建字段。
4. 绑定字段后，在字段配置中编辑名称、默认值和基础校验，点击“保存字段设置”一次应用。所有绑定该字段的组件共享配置。字段 ID、类型和数据路径在创建后不通过本面板修改，避免不完整的引用迁移。
5. 在同一表单容器里添加按钮，将按钮类型设为 submit。进入预览模式，验证输入、必填错误、数值范围及提交状态。“页面状态”页签显示表单值、错误、isSubmitSuccessful 和提交次数。

当前支持 required、min/max、minLength/maxLength、pattern 及自定义错误文案。数值初始值留空表示 null；布尔字段使用勾选框编辑默认值。已有表达式规则以只读方式展示，保存基础设置时保留规则顺序、表达式内容和 when/disabled 条件。动态字段组、计算字段与整单规则保持原有定义，本面板尚不编辑这些结构。

表单容器绑定和输入组件的字段绑定彼此明确：容器决定提交哪个模型，字段引用决定读写哪个字段。修改容器模型前需要先解除受影响的后代字段绑定，模型中的字段也不会自动生成输入组件。跨模型移动、插槽和导入兼容性见 [字段绑定作用域](form-binding-scope.md)。

## 文档命令与一致性

新增 EditorDocument 命令：

| 命令                     | 行为                                                   |
| ------------------------ | ------------------------------------------------------ |
| createForm               | 创建完整模型并绑定当前表单容器                         |
| bindForm                 | 绑定、重新绑定或解除容器绑定                           |
| createField              | 创建根字段，可同时绑定指定字段组件                     |
| bindField                | 绑定、重新绑定或解除字段绑定                           |
| updateField              | 修改字段名称、初始值和规则，保留身份、路径、类型和条件 |
| removeField / removeForm | 引用检查后删除模型定义                                 |

所有命令克隆当前定义，完成修改后复用 compileApplication 校验，成功才发布快照、增加一步历史。类型不兼容、重复 ID、路径冲突、非法正则、长度校验错误和矛盾范围不会改变文档、选择或 redo。可撤销、重做和 JSON 往返。

字段绑定移除组件上由表单管理的固定属性（value/checked、label、required 等），保留其他属性及无冲突事件。若组件已有这些属性的表达式/引用、change/blur 事件、when 或 repeat，命令拒绝操作并提示先处理冲突，避免静默丢失业务逻辑。字段定义保留原位，解除某个组件绑定不会删除字段。

解除字段绑定时，从模型初始值恢复为静态 label/value/checked，required 只在物料声明该属性时恢复。数字模型初始值 null 无法作为未绑定组件的 number 属性，因此转换为 0；不会把预览中的用户输入写入 Schema。撤销可完整恢复此前的绑定或属性。

## 删除与依赖边界

引用检查覆盖节点及插槽子树的 field/formId、属性和动作参数、页面进入动作、字段条件、校验规则及动态字段组。fieldRef 按字段精确匹配；formValues、JavaScript 表单表达式或动态访问按整个模型保守处理。目标模型有 TypeScript 计算函数，或代码物料通过固定 formId 属性引用模型时，阻止删除其中的任何字段。提示中列出引用位置。被删除定义自身的规则随之消失，不计为外部引用。

不遍历 literal JSON 的业务内容和 extensions 中的 opaque 数据，也不通过猜测字符串重写引用。任意第三方 TSX 内部硬编码的 useForm ID、隐藏在动作实现/扩展中的依赖无法从当前 Schema 自动发现，宿主扩展需要显式声明依赖；现有 formId 约定不等于通用的代码依赖分析。

模型的最后一个字段无法删除，除非模型还包含动态字段组。可以先解除使用它的容器及字段引用，再删除整个模型。删除视图组件不会连带删除业务模型。

## 草稿、预览与验证

字段配置采用显式保存；无效草稿留在当前面板并显示错误，运行时继续使用上一次有效定义。选择其他节点、关闭配置或文档发生更新可能丢弃未保存草稿。提交成功后沿用现有策略重建预览实例并重置运行数据，单纯选择节点不重置数据。

表单绑定接通已有 handleSubmit 验证与状态管理，不自动配置业务提交动作。新建表单没有 onSubmit 动作时，提交成功仅表示本地校验和提交流程完成；现有采购表单的动作保持原样。业务动作仍由注册的 TypeScript 函数执行，React 组件继续使用普通 TSX、Hooks 和原生事件；事件配置面板属于后续阶段。

自动化覆盖空表单创建原子性、字段类型筛选、绑定和解绑、保留高级条件与规则、冲突拒绝、默认值、路径/规则错误、删除引用检查、单步撤销及 JSON 往返。工作台集成测试从空白表单开始，通过界面创建姓名和金额字段，验证空提交、金额为 0 的错误、有效提交和状态快照。

实际浏览器通过界面在组件组合页添加表单、姓名、金额和 submit 按钮，验证 required/min 错误，以及姓名和金额填写后 isSubmitSuccessful 为 true；该验收流程未手动编辑 JSON。截图见 field-binding-preview.png。
