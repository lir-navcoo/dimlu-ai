# 组件显示条件与循环

在组件检查器的“逻辑”页签配置 `NodeSchema.when` 和 `repeat`。协议版本与 JavaScript 表达式子集保持不变，使用 React 的条件渲染与稳定 key 语义；合法的旧条件与循环无需迁移。过去只能在运行时报错的已知错误类型和明确缺失的作用域，现在会在提交修改或导入时拒绝。未知表达式或嵌套路径的实际结果仍由运行时校验。

## 显示条件

显示条件支持固定布尔值、状态、表单字段、数据源和表达式；不设置表示始终显示。条件结果必须为 boolean，不作 truthy 转换。循环组件对每条记录分别判断条件。设计模式下，false 条件或空循环保留可选择的占位；预览不显示对应物料。多个循环实例编辑的是同一个 Schema 定义。

直接绑定字段的组件不能设置节点条件或循环。字段条件属于字段定义；可使用外层布局控制视图，但容器隐藏不会让内部字段停止校验。表单容器不能循环，循环视图也不会建立多个独立表单。需要多行输入时使用动态明细物料。

## 循环数据、变量与标识

启用循环后明确设置数组、记录变量、可选索引变量和记录标识。循环数据在外层作用域计算，本次循环的记录和索引变量此时尚未引入。记录标识、显示条件、当前组件属性、样式及事件使用本层作用域。界面分别显示两类可用变量。

索引变量留空时为 `index`。记录变量不能与有效索引同名，也不能使用保留字。保留已有的变量名语法，例如 `row-data` 通过 `scope["row-data"]` 读取。子循环与插槽参数可以合法遮蔽外层变量。

记录标识必须明确配置为字符串或有限数字，各条记录不能重复；数字 `1` 与字符串 `"1"` 是不同身份。建议使用稳定的业务记录标识表达式，例如 `scope.item.id`，平台不会自动添加 `.id` 或在失败时使用随机值/索引代替。明确使用 `scope.index` 是合法的，但它跟随位置，排序或插入记录后不能保持原记录的 React 状态。未知结果的非法标识、重复标识和非数组数据会形成运行时局部错误。

## 原子应用与草稿

条件与循环各有独立会话草稿，输入不会发布不完整循环；点击“应用组件逻辑”时两组配置一次校验、一次提交、一次撤销。因此可同时修改变量别名及使用它的条件/标识。输入不合法时保留草稿、当前定义、撤销与重做。

切换页签、节点或页面仍保留未应用输入。Undo/Redo 或其他修改使来源定义改变时，草稿显示冲突，需明确“确认使用草稿”后再应用。“恢复显示条件”和“恢复循环渲染”只移除对应声明并清理对应草稿/错误，另一组输入保持；“恢复全部组件逻辑”也清理已折叠分组的草稿。恢复失败时不清空输入。

循环修改会检查保留下来的属性、样式、条件、事件、子循环和插槽表达式。删除、重命名或新增变量不能悄悄改变这些表达式绑定的变量来源，即使相同名称仍由外层提供也会拒绝。已经由子循环或插槽独立提供的同名变量不受影响。平台不会改写表达式或删除依赖。`scope[String("row")]` 和直接读取 `scope` 仍合法；因无法静态确定具体变量，对这类保留表达式的循环修改会保守比较完整作用域。样式表达式继续使用已有的明确变量规则。

底层 `EditorDocument.setNodeLogic(pageId,nodeId,patch)` 按自有属性区分操作：未提供保留、显式 `undefined` 删除；输入深拷贝，失败不改变计划、历史或选中项。状态、表单与数据源的既有删除检查仍会保护只出现在条件或循环中的引用。运行时数据与会话草稿不会写入应用 JSON。
