# 编辑器 v0.3：拖放编排

本阶段在现有文档命令上加入物料拖入、已有节点重排、跨容器及具名插槽移动。拖放会话属于编辑器临时状态，不进入应用 Schema；普通运行环境不依赖拖放模块。

## 操作

- 从左侧物料面板拖入新组件，从组件树手柄或画布选中框手柄移动已有组件。
- 纵向节点按上下半部判断前后，横向 flex/grid 节点按左右半部判断，并支持反向排列。画布显示对应方向的插入线，组件树同步提示。页面与容器内的空隙按最近子节点确定插入位置。
- 空容器、具名插槽和页面末尾提供显式落点；这些区域在编辑模式下始终保留，拖动和高亮不改变布局或目标尺寸。具名插槽使用自己的落点，不猜测卡片内部的业务 DOM。
- 手柄按空格或 Enter 开始键盘操作，焦点进入“拖放位置”，选择目标后确认；Escape 或取消按钮结束拖动。
- 指针移动超过 6px 才开始拖动；靠近滚动区域或窗口上下边缘时自动滚动。松手时重新命中实际位置，避免滚动后仍使用旧落点。画布手柄保持挂载，保留指针捕获。
- Escape、当前指针取消或失去捕获、窗口失焦，以及切换模式、页面或修改文档，都会取消会话；其他指针的取消不会影响当前拖动。画布和组件树之外松手不会修改文档。

显示条件不满足、字段当前不可见或循环为空的节点在编辑模式显示原因占位，支持选择及结构定位；预览模式按原规则隐藏。成功放置后，超出当前视口的选中组件会滚动到可见位置。第三方组件自行返回 null 或通过自定义 CSS 隐藏的情况仍需专用适配。

无效落点会显示拒绝原因，例如移动到自身子树、目标物料不接受子节点、插槽不存在或移动后丢失作用域。拖放只支持同页移动，循环实例拖动修改对应的共享 Schema 定义。

## 意图与文档命令

`packages/editor/drop.ts` 定义与 DOM 无关的两类对象：

```ts
type DragSource = { kind: 'material'; component: string } | { kind: 'node'; nodeId: string };

type DropIntent =
  | { kind: 'before' | 'after'; nodeId: string }
  | { kind: 'inside'; parentId?: string; slot?: string };
```

`resolveDrop` 把节点锚点转换成 `{ parentId?, slot?, index? }`。同列表向后移动时扣除源节点占用的一项，保持 `moveNode` 的“移除源节点之后的索引”语义。放入容器或插槽省略 index，表示末尾。

`EditorDocument.checkInsert` 和 `checkMove` 与正式命令共用草稿准备过程，执行同一编译校验；预检不发布快照、不增加历史、不改变选择，也不消耗正式 ID。拖动会话按落点缓存预检结果，文档变化时取消整个会话。

拖动期间不预先移动真实节点，也不改写文档。松手后由现有 `insertNode` 或 `moveNode` 再校验并一次提交；成功拖放对应一步撤销，无变化移动不增加历史。JSON 导出只包含提交后的应用定义。

## React 适配

`RuntimeRenderer` 在 nodeDecorator 之外增加可选 slotDecorator 和 childrenDecorator，编辑宿主据此在实际具名插槽及空容器内部放置提示。nodeDecorator 可收到 inactiveReason，描述被引擎隐藏的节点；不提供装饰器的普通运行环境继续输出空内容。业务组件继续使用原生 React props、事件和插槽回调。

`src/editor/DragDrop.tsx` 管理 Pointer Events、键盘会话、提示和自动滚动，`hit-test.ts` 负责 DOM 落点判断。节点 DOM 测量与实际排列方向共用 `geometry.ts`，选择框和落点覆盖层不承担业务渲染。空 children 容器的占位通过 childrenDecorator 传入实际物料内部，避免相邻占位形成错误的额外 flex/grid 项。

选择、开始及取消拖动不会重建运行实例，React 局部状态保持。成功修改 Schema 仍沿用现有运行策略，重建实例并重置预览数据。

## 开发热更新

React Fast Refresh 会保留 useState 中的旧类实例。文档实现新增方法后，界面可能已经更新而旧实例仍缺少 checkInsert/checkMove，导致所有落点被错误拒绝。App 通过 refreshEditorDocument 检查文档实现身份，必要时用当前 Schema 和选中节点重建文档，避免继续调用过期实例。这个开发过程保留应用定义和选择，但会重置撤销历史及预览运行状态；正常编辑和普通组件重渲染不走该重建分支。

## 验证及边界

自动测试覆盖同列表索引归一化、具名插槽、预检无副作用、原子提交及单步撤销、循环和作用域拒绝、画布键盘焦点、手柄不卸载、稳定落点、横向与空隙命中、隐藏节点占位、模式隔离、原生状态保持、指针阈值、松手重新命中、捕获丢失取消及旧文档实例升级。

实际浏览器验证了物料指针拖入、画布手柄重排、键盘放入 footer 插槽、非法作用域提示、撤销、Escape 后局部状态保持，以及下载 JSON 后刷新再导入还原。桌面与 390px 布局截图见 `drag-preview.png` 和 `drag-mobile-preview.png`。移动端仅验证浏览器视口布局，尚未在真实触摸设备验证手势。

本次回归进一步复现并修复 footer 落点偏移；实测开始拖动和高亮后 footer 的位置、尺寸保持不变，真实指针放置结果处于 footer。还验证了横向节点重排、全部 13 种可插入物料的默认内容及占位可测量、位于视口内，且没有节点渲染错误。修改文档实现触发真实热更新后，已编辑标题和选择保留，拖放预检仍可用。修复后截图见 `drag-fixed-preview.png`。

当前每个不同落点首次预检会编译整份应用，节点测量也尚未做大页面性能优化；自动滚动和复杂嵌套布局仍需更大场景验证。尚不包含跨页面拖放、多选拖放、复杂网格的专用放置策略或第三方 Portal/Shadow DOM 的通用适配。下一步可连接字段绑定面板，明确字段与状态引用的编辑流程，再按真实页面规模优化编译和测量。
