# 物料元数据与属性编辑器 v0.1

当前实现完成从文档编辑到运行预览的最小闭环：选择组件、修改属性、增删节点、撤销重做、导出 JSON、刷新后导入还原。编辑器状态和物料元数据都不进入应用 Schema。

## 三个独立模型

| 模型        | 职责                                                             | 来源                           |
| ----------- | ---------------------------------------------------------------- | ------------------------------ |
| 应用 Schema | 可序列化的页面、状态、字段、属性绑定、事件和插槽                 | `packages/schema`              |
| 运行契约    | props 类型和必填性、事件、children、插槽参数、版本与字段适配能力 | `packages/runtime/registry.ts` |
| 编辑元数据  | 标题、图标、分类、属性分组、setter、插入默认值                   | `packages/editor/metadata.ts`  |

宿主的 `src/editor/catalog.ts` 覆盖已有 15 个物料。`validateCatalog` 检查属性名称、setter 类型、选项值、默认值和必填属性；启动时执行。类型和必填规则来自运行契约，元数据提供编辑呈现。

支持 text、number、boolean、select、JSON setter。枚举选项是编辑建议，暂未提升为运行契约中的枚举约束；已有自定义字符串值会保留并显示。

## 统一编辑文档

`packages/editor/document.ts` 是不依赖 React 的 TypeScript store，React 通过 `useSyncExternalStore` 订阅稳定快照。

```text
属性面板 / 组件树 / Schema 编辑器 / 文件导入
                       ↓
                  EditorDocument
                       ↓
          克隆草稿 → 修改 → compileApplication 校验
                       ↓ 成功
          不可变运行计划 + 历史 + 选中状态一次发布
                       ↓
                 React 预览与编辑界面
```

命令包括 `setProp`、`insertNode`、`removeNode`、`replace`、`importJson`、`undo`、`redo`。所有应用内容修改先通过结构、引用、表达式与物料契约检查，失败时抛出异常，当前文档、历史和运行实例不变。`exportJson` 仅导出最后接受的应用定义。

历史默认最多 100 步，保存不可变运行计划和选中状态。同一次属性焦点会话内的连续有效修改合并为一步；失焦、切换选择和撤销重做会结束分组。新编辑清除 redo 分支；无变化操作不创建历史，也不清除 redo。整个应用共用历史，页面选择本身不进入历史。

选中状态采用 `pageId + nodeId`，不存 DOM 或 React 实例。树遍历同时覆盖 children 与具名插槽；删除选中子树后选择父节点或相邻节点，撤销恢复原选择。插入节点检查容器/插槽能力、生成页面内唯一 ID，并声明插入物料依赖；具名插槽初始化包含运行契约要求的参数。底层支持指定插入索引，当前 UI 提供页面末尾、选中容器末尾、选中组件的插槽末尾。

## 属性绑定与草稿

- 固定值按 setter 转换为真实 JSON 类型，数字不会把空输入默认为 0；非法 JSON 和类型错误不会替换预览。
- 表达式使用现有 JavaScript 表达式子集和同一编译器。输入未完成时保留局部草稿并提示错误；有效时立即提交。切换到表达式先显示空草稿，原属性继续生效，直到输入有效表达式。
- 已有 `stateRef`、`fieldRef`、`formValues` 以只读引用模式显示，只有显式切换固定值或表达式后才替换。尚未提供可视化引用选择器。
- 可选属性可以切换为“未设置”以删除属性；必填属性不能在面板中删除。
- 绑定表单字段的 value、label、required 等由表单内核管理，面板只显示管理来源；placeholder、hint 等展示属性可继续编辑。字段模型与规则仍通过 Schema 编辑。
- 草稿不参与导出、撤销或持久化。离开属性面板、切换节点或接受其他文档更新时，未提交的局部草稿可能丢弃。导出内容以预览采用的定义为准。

编译检查不能保证表达式在所有运行数据下返回正确类型；求值和渲染错误仍由运行时诊断与节点边界处理。代码扩展继续使用普通 TSX、Hooks、原生事件和注册的 TypeScript 函数。

## 导入导出与验收

工具栏下载完整 `dimlu-application.json`。文件导入与 Schema 面板“校验并应用”调用同一文档命令，均可撤销；非法文件不会影响当前页面。Schema 面板展示当前接受的定义，可编辑整份应用。引用、动作、插槽、表单及命名空间扩展都保留。

验收路径：

1. 采购申请页默认选中 `purchase-heading`。
2. 在右侧修改“标题”，中间预览同步更新。
3. 点击撤销恢复原文，重做恢复修改。
4. 导出 JSON，刷新页面，再导入文件，标题还原。
5. 选择插槽卡片，可以向 header/body/footer 插入组件；删除后可撤销。

已完成实际浏览器下载、刷新、文件导入，以及桌面和 390px 窄屏检查。截图见 `editor-preview.png` 和 `editor-mobile-preview.png`。

## 当前边界和下一步

每次有效文档更新（包括撤销重做）都会重建页面运行实例，重置预览输入、React 局部状态，并取消旧动作。仅选择节点保持运行计划身份，不重置预览。尚未做跨版本运行状态迁移或热更新协调。

面板新增的普通输入组件使用固定受控值，在未连接 change 事件时明确设为只读；后续需通过字段绑定或状态和事件构成可输入的数据链路。依赖表单上下文的采购明细、表单状态物料不提供直接插入入口。

画布点选、编辑/预览模式和节点移动/复制已在 [编辑器 v0.2](./editor-v0.2.md) 补齐。尚未包括拖拽、事件/字段规则面板、自动保存、多人协作和出码。对较大文档，当前每次编辑克隆并编译整份应用的成本需要实测，再考虑增量校验、历史补丁和预览状态保留。
